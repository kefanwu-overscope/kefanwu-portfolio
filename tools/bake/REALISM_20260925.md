# Studio lighting bake · 2026-09-25

`realism_bake.py` rebakes the existing approved room in Blender 4.5.9 LTS /
Cycles. It keeps the room dimensions and furniture layout. The source is the
original `models/baked/room-baked.glb`; a browser export of the actual static
cabinetry, workbench, chair, lamp and props adds missing contact shadows and
indirect occlusion. The exhibit models remain independently lit at runtime.

The final bake used an RTX 5080 through OptiX, native 4096×4096 maps, 256
samples, six diffuse bounces, and a neutral area-light rig for the two lamp
states. Raw lighting contains DIFFUSE direct + indirect, without albedo.
OpenImageDenoise processes the baked color buffer. The room GLB, its normals,
geometry, materials and both UV sets are copied byte-for-byte. The source has
6,643 separate UV islands; experimental repacks were rejected because they
reduced usable atlas area. The final delivery preserves the verified original
atlas. The obsolete pendant and desk pad remain hidden using existing runtime
rules and are excluded as occluders in the bake scene.

Source `.blend` files, uncompressed float arrays, raw/denoised EXR images,
Cycles proof renders and source SHA-256 hashes are deliberately kept outside
the deployment tree in `../.codex/realism-20260925/bake-final/`. The static
caster export is `../.codex/realism-20260925/static-casters.glb`. Preserve that
directory when archiving source material. Cycles previews show the bake scene,
including empty exhibit bays, rather than claiming to match browser rendering.

Reproduce from the site root (PowerShell):

```powershell
& 'C:/Users/oc/.cache/blender/blender-4.5.9-windows-x64/blender.exe' --background --python tools/bake/realism_bake.py -- --root . --evidence ../.codex/realism-20260925/bake-final --casters ../.codex/realism-20260925/static-casters.glb --resolution 4096 --samples 256 --states off on --deploy models/baked/realism-20260925
```

Use Python with NumPy and Pillow to encode each delivery quality:

```powershell
python tools/bake/encode_realism.py --evidence ../.codex/realism-20260925/bake-final --output models/baked/realism-20260925 --source-resolution 4096 --resolution 2048 --range 16
python tools/bake/encode_realism.py --evidence ../.codex/realism-20260925/bake-final --output models/baked/realism-20260925 --source-resolution 4096 --resolution 4096 --range 16
```

The default 2K image is an exact 2× area downsample of scene-linear 4K values,
performed before RGBM encoding. The native 4K texture is optional. Both states
and qualities share the original geometry's second UV atlas. The dated GLB is
identical to the original, so either geometry URL has the same UV contract.

Runtime texture contract:

- RGBA8 lossless PNG; scene-linear RGBM range 16; decode `rgb * alpha * 16`.
- `NoColorSpace`, `flipY=false`, `channel=1`, `premultiplyAlpha=false`.
- Linear filtering without automatic mipmaps, matching the runtime loader.
- Decode with `createImageBitmap` options `premultiplyAlpha:'none'` and
  `colorSpaceConversion:'none'`. Alpha carries data; avoid a canvas roundtrip.
- Blend decoded light values, not encoded RGBM pixels, between lamp states.
- Both probes are scene-linear Radiance HDR, native 512×256, rendered while
  the static props' imported PBR textures are still attached.

`calibrate_diffuse.py` measures the lighting units with a white Lambertian
plane in a unit-radiance world. The measured bake RGB is exactly `[1,1,1]`;
therefore the lightmap contains irradiance divided by π. When passing it to
Three r185's `RE_IndirectDiffuse`, multiply decoded RGB by π and the desired
lightmap intensity. Replace architecture diffuse lighting once and retain
physical specular terms; adding the bake to live diffuse would double-light
the architecture. The calibration record is
`../.codex/realism-20260925/diffuse-calibration.json`.

Initial room GLB + off 2K lightmap + off probe totals 3,130,937 bytes versus
7,311,915 bytes previously, a 57.2% reduction. All four RGBM encodes have zero
clipped channels and exact PNG byte-channel roundtrips.
Byte hashes, clipping/quantization errors and native-resolution provenance
are in `bake-final/bake-manifest.json` under `encodedQualities`.
Browser integration may publish content-hashed filenames from those outputs.

## Desktop detail map

`bake_desk_detail.py` loads the accepted off/on source blends and bakes a
native 512×512 planar receiver 0.2 mm above the tabletop at 256 samples. The
receiver is invisible to camera, shadow and secondary rays; the unchanged
room and props remain the actual occluders and bounce surfaces. This bypasses
the original desktop's fragmented low-density atlas without changing geometry.

`encode_desk_detail.py` writes `desk-off.rgbm.png` (159,369 bytes) and
`desk-on.rgbm.png` (155,605 bytes), using the same RGBM16 and irradiance/π
contract. Sample only the upward-facing desktop; retain the original atlas
for sides and bevels. With `flipY=false`, the mapping is:

```glsl
vec2 deskUv = vec2((worldX + 0.925) / 1.85, (worldZ + 0.45) / 0.9);
```

The PNG top row is Three Z = −0.45 and its left column is X = −0.925.
`../.codex/realism-20260925/desk-detail/` contains source blends, EXRs, arrays,
preview images and the exact bounds/source hashes in `desk-manifest.json`.
The off detail texture raises the initial lighting/geometry bundle to
3,290,306 bytes, still 55.0% below the original 7,311,915-byte bundle.

## Runtime and release packaging

`experience-baked-material.js` loads PNG data with straight alpha and no color
conversion, blends decoded radiance, and replaces baked diffuse after the r185
lighting chunks. Direct and environment specular remain. The desktop uses the
planar detail map for upward-facing surfaces and the original atlas for sides.
The site's current ACES photographic grade uses a 0.7 bake intensity; this is
a presentation setting, not a measured illuminance claim.

Run `node tools/bake/package_realism.cjs` after the verified encodes. It writes
content-addressed copies, `experience-baked-assets.js`, and immutable cache rules.
Only the nine files named in `../.codex/realism-20260925/asset-commit-files.txt`
are new runtime image/geometry assets. Preserve legacy files for old clients.
Raw masters, `.blend` files, experiments, and the static caster export remain
outside the deployed site. UV repacking experiments were rejected; the shipped
geometry and both original UV sets are byte-identical to the preceding release.
